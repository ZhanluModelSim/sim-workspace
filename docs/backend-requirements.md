# 后端职责与核心流程确认

状态：2026-10-30 需求讨论记录；尚未开发代码。本文保存跨仓职责与已确认行为，不冻结类名、函数签名或字段 schema。组件内部实现设计后续归对应业务仓库。

依据本轮用户确认，以及作为讨论素材的 [issue #1：titan 上下游任务汇总](https://github.com/ZhanluModelSim/sim-workspace/issues/1)、[issue #2：Backend 原先设计](https://github.com/ZhanluModelSim/sim-workspace/issues/2)。issue 描述旧设计，不整体继承；与本文冲突处以最新确认为准。

此前临时分析的 workload-model-platform 仅用于了解业务职责，不作为开发必读或参考实现。当前系统按自己的需求开发，不继承其组织、接口和算法。

本文中的“已确认”是需求，不表示已实现；“建议”尚未确认；“待定”不允许开发时自行补成公共约定。指标种类、公式、分母和汇总 schema 暂不确定。

## 已确认：职责与入口层次

| 归属 | 职责 |
| --- | --- |
| 训练／推理发生器 | 各自生成负载和相关事实，保持独立配置与入口；平台不反向规定两侧统一参数空间 |
| operator-performance-models | 算子特征归一、roofline 实现、预测后端注册与选择、fallback、按实际目标硬件预测及来源信息 |
| sim-platform | 负载适配、公共图处理、预测调用与缓存、vec scaler、L1 DES、MoE A2A 修正、offload 分析、L2 阶段组织及结果汇总 |

后端是这些能力的协作边界，不要求合并成一个 PerfBackend 大类，也不让组件导入平台内部实现。

核心入口按两个层次理解，名称和签名待定：

- **算子预测入口**：接收算子特征、目标硬件及模型选择配置；返回原始耗时、必要分量、成功／缺失状态及实际使用的后端和来源。分量的具体字段待定。
- **L1 图评估入口**：接收单图、默认硬件和局部覆盖、预测与修正配置；完成预测、vec scaler、DES 和图后处理，返回原始及修正结果。

训练／推理上层入口分别调用可复用能力，不因此强制统一 TaskSpec、run_task 或配置基类。负载与结果可以通过内存对象交付，导出不作为核心调用前提。

## 已确认：核心流程

```text
训练／推理负载
  → 平台适配与必要的图处理
  → 算子预测（特征归一、硬件解析、模型选择、缓存、预测／fallback）
  → vec scaler
  → L1 DES（执行依赖、资源约束、重叠与时间线）
  → MoE A2A 后处理
  → 供阶段组织与端到端汇总消费

L1 时间线 + 上游数据量 + 硬件带宽
  → offload 分析
  → 端到端附加耗时
```

L1 负责阶段／单图，L2 负责阶段实例及跨阶段依赖；无 PP 时仍按此前确认的 `(F → B) × GA → O` 方向组织。offload 折算本轮明确不涉及 L2，不需要为它先扩展 L2。

保持训练发生器有意提供的 FSDP 通信视图，不以此流程为由打开完整源图。

## 已确认：两种必需修正

### vec scaler：DES 之前

- 对全图所有 vec 算子的 costmodel 输出耗时乘以固定系数，再交给 L1 DES。
- 因而修正会影响 DES 生成的时间线和总耗时。
- 保留原始预测、系数和修正结果；缓存原始预测，避免修改系数就重新预测或重复打折。
- vec 分类依据、系数有效范围、分量字段是否及如何同步缩放待定；不直接继承旧环境变量名和默认值。

### MoE A2A：DES 之后

- 根据 FQN／module path 或算子标识，定位每个 MoE 区域。
- 从 L1 DES 结果中提取该区域的通信与计算时间，按固定规则和比例折减通信时间。
- 这明确替代旧 issue 中 DES 前进行 MoE A2A 折算的安排。
- 保留原始 DES 结果与修正记录。具体区域匹配、时间提取、折减公式、比例、端到端汇总方式，以及是否生成修正时间线均待定；不能把后处理值冒充重新调度后的时间线。

两种修正属于不同阶段；不因都叫修正就统一成同一个处理位置。后处理不得重复应用，具体机制待实现设计。

## 历史方案：offload 后处理

以下窗口后处理是早期方案。激活与优化器 offload 均已由文末执行图职责的新确认替代。保留旧方案作为独立窗口分析的背景，不在主流程自动补偿、不与执行图节点重复计费。

需要支持 AC offload／load 和优化器 offload 的分析。核心诉求为需求带宽、给定带宽下的传输时间及溢出对端到端时间的影响。

1. 从 L1 的几张阶段图及时间线中，以 FQN（module path）截取各层时间。
2. 对齐上游提供的数据量与相应的加／卸载计算窗口。
3. 求带宽时：`需求带宽 = 数据量 / 可用窗口时长`。
4. 给定硬件带宽时：`传输时间 = 数据量 / 带宽`，`溢出时间 = max(0, 传输时间 - 可用窗口时长)`。
5. 汇总溢出，按相应阶段执行次数补充到端到端时间；保留原值、补偿量和修正值。

这是消费 L1 结果的后处理，不将传输重新插入 L2 调度，也不要求重跑 L1。公式使用一致单位；零窗口、缺失数据和无效带宽如何呈现待定，不能据此伪造零开销。

**必须取得真实训练负载后再确定**：FQN 层级、重算等重复实例的区分、前后向窗口与数据量匹配、相邻层配对、优化器窗口，以及阶段次数的具体来源。不能提前固定为旧 CSV 列、旧文件名或旧窗口算法。

offload 与 MoE A2A 修正之间使用原始还是修正窗口、如何组合端到端补偿，仍待明确。显存收益与峰值补偿的具体口径也未在本轮确定，不继承旧常数和公式。

## 已确认：预测模型与硬件

- 当前只采用 **roofline**；同时保留多后端注册、选择和 fallback 的组织能力，不要求当前实现其他模型。
- 默认预测后端链可配置，允许对特定算子或算子集合覆盖选择。具体匹配规则和优先级待定。
- 图有默认硬件，允许部分算子使用其他硬件配置；先解析实际硬件，再预测和查询相应缓存。
- 记录实际命中的后端、硬件及 fallback 情况。只有 roofline 可用时，未覆盖仍须显式报告，不能假造兜底成功。
- 局部硬件覆盖目前指算子性能估算；不自动代表已要求异构部署、跨设备迁移和通信仿真。
- 不继承旧模型清单、中心公式、通信 V1/V2 开关和旧场景预设。roofline 的具体公式、硬件特征及校准方式待组件设计。

fallback 的“不支持／输入非法／运行失败”分类、触发条件、缺失结果处理，以及失败缓存策略均待定。

## 已确认：预测缓存

平台组织预测调用与缓存加速。缓存保存**原始算子预测**，不保存 vec 折算后的值；不携带某次图执行的节点身份、起止时间。

缓存身份应涵盖实际影响预测的特征：shape、dtype、layout、相关属性、解析后的硬件配置、模型及归一版本、预测配置。模型路由及 fallback 策略不能因旧缓存命中而被绕过。

修改 vec 系数可以复用原始预测，但须重新执行后续受影响的 DES；修改图依赖同样不能复用旧时间线。缓存介质、容量、失效、并发与持久化策略待定。

## 已确认：推理首期与内存边界

补充依据：[推理仓需求／功能文档](../inference-models-simulator/docs/推理仓目录结构与功能设计.md)，阅读版本 `8a9d09d293df4df848091c145be6078d3f01689a`，以及用户随后确认。该相对链接需先获取推理仓；文档中的目录和接口示例不因此成为冻结实现。

- **调用计划与 L2 分工**：推理仓描述执行哪些图、调用次数、数据与状态绑定、依赖和分支；平台负责这些调用在目标资源上的执行与完成时刻。draft/verify、KV 更新等模型语义归推理仓，平台不重新推断。这是职责边界，不表示首期实现全部调用计划。
- **首条推理链路**：固定配置的一次 prefill 或 decode 调用，明确本次 query 长度和已有 KV 长度，输出单次执行结果；后续再扩展图集合与调用计划。代表图乘 N、KV 逐步增长、投机接受行为分别明确建模，不默认等价。本轮未选定首个模型或要求支持所有组合。
- **首期内存**：训练和推理负载仓均只需交付静态内存信息，平台首期不接入任何 L1／L2 内存回放。静态结果不标记为 DES 动态峰值。
- **后续统一范围**：跨仓归一不只包括图 G，还包括对应内存信息；后续为训练和推理增加基于执行时序的内存回放。具体表示、事件锚点和统一 schema 待设计，不要求发生器改成相同内部结构，也不要求本轮建立动态回放接口。
- **AF/PD**：真实分离部署中子图的 L2 调度暂不做，不因推理文档提及该场景就纳入平台首期。算子局部预测硬件覆盖仍保留，不等同于已支持分离部署仿真。

以上范围不改变已经确认的 offload 后处理：仍根据 L1 时间窗口与上游数据量计算溢出，补充端到端时间；这不是内存回放。

## 进程内共享配置：已确认边界与建议

**用户提出的方向**：提供 global args 一类的单进程共享配置对象，集中可读可写、便于查询，避免 pipeline 各处散落读取环境变量。支持由环境变量、CLI 或程序传入的 args 初始化。单例是用户偏好的实现方式，允许提出更合适设计；目前未确定 API。

**已确认的兼容边界**：global args 管理进程默认设置和公共开关；每次任务解析后的模型配置、运行配置和可变执行 context 独立保存。搜索候选之间不通过改写共享任务状态互相覆盖。这不要求训练与推理共用配置类型。

**建议方案，尚未确认**：在平台提供集中配置访问入口，内部使用有类型与校验的配置对象，而不是任意全局字典；支持读取、受控更新和查看当前生效值及来源。环境变量在初始化时解析，CLI 和函数参数归一后进入同一配置对象，业务阶段从该对象读取。

在已确认的默认配置与任务配置分离边界下，建议评估开始时生成配置快照供各阶段使用，修改默认值影响后续评估；如需运行中修改当前任务，明确生效边界。这兼顾集中查询与可复现性，但快照方式不是已确认要求，不把用户的可写诉求改成全局只读。

建议组件通过参数或注入的配置视图取得所需配置，避免独立算子仓／发生器反向导入平台单例。共享配置管理设置，不替代负载和结果的数据交付。

待讨论：

- 默认值、环境变量、CLI、函数参数之间的覆盖优先级，以及冲突／未知字段处理。
- 单例的具体归属、初始化／重置时机、未初始化访问行为及查询接口。
- 运行中修改的生效范围、连续任务之间的隔离、线程／异步并发策略；单进程共享不意味着跨进程共享。
- 如何把实际生效配置与结果来源、缓存键一致关联，防止运行中设置变化造成错误复用。

## 2026-10-31 最新确认：预测与分类解耦

costmodel不承担算子分类和执行资源计划，Estimate移除category/resources，仅返回耗时、synthetic标记和预测明细。平台按名称及图语义自行分类并决定执行资源；最新确认未命中名称规则默认vec，不通过预测结果补分类；节点及OpFeatures移除重复kind。已有图上resource_requirements是平台显式执行要求，不是训练仓分类输出。

不再信任或消费上游communication_input_bytes、事件volume_bytes等派生统计，公共图删除input_bytes，预测输入也移除相应属性。后续通信adaptor按张量参数角色、shape/dtype和通信语义提取工作量，模型再计算成本；当前不实现通信/topo公式。训练仓内假后端和派生统计清理留待后续。

## 最新确认：MFU / MBU（2026-10-31）

MFU为cube类算子的纯理论计算时间除端到端仿真时间：按dtype对应位宽汇总cube FLOPs，除对应chip峰值，不计利用率、HBM、静态开销，也不包含mix的FLOPs。MBU按所有算子读写访存量除chip HBM峰值带宽，再除同一端到端时长。训练分子按(F+B)*GA+O汇总，公共部分不包含GA逻辑。先实现独立指标组件，主流程后续接入；其余指标口径仍待确认。实现与边界见平台docs/utilization-metrics.md。

## 最新修正：区分 HFU 与 MFU（2026-11-02）

此前全部cube理论时间除端到端时间的计算归为HFU；MFU排除上游标记recompute的cube FLOPs，仍使用完整端到端分母。MBU保留所有读写，包括重算访存。公共图已保留execution_kind，指标转换仅判断是否等于recompute，省略默认非重算，兼容推理。训练全部／重算工作量均按(F+B)*GA+O展开。此确认替代前节MFU未排除重算的定义；独立指标组件暂不接主流程。

## 训练统计确认（2026-11-02）

训练只统计单卡token吞吐：实际GBS*上游seq_len/总卡数/最终端到端秒数，seq_len加入公共训练事实（替代早期从请求读取的方案）。Top算子按name和name+shape/dtype两种公共分组，训练以F/B乘GA、O乘1的权重输入，不复制算子行。通信域统计串行时间和、优先级掩盖后的暴露时间和及占比。算子／通信统计不包含offload后处理拖尾；idle可当作独立算子记录，使正时长下总暴露占比为100%。端到端时延及吞吐使用最终耗时，统计分母使用DES阶段加权时长。

训练汇总改为training.json，分config/results；配置区保留归一上游事实、请求、平台设置和字段来源。seq_len来自上游正式dataloader输入描述，缺失不可用请求冒充。模型仅标识与回传的显式reported_overrides，不保存完整默认配置树。

最新结果展示收敛：training.json先results后config；展示不输出sources，内部来源仍保留。chip和未来topo仅名称或绝对路径。统一入口接入MFU/HFU/MBU，缺失工作量明确不可用；静态显存从上游内存对象直接写入results.memory，不依赖mem文件。

## 2026-11-02 已确认：激活 offload 执行图职责

- 训练 simulator 生成 D2H/H2D 传输节点和等待依赖，并基于同一候选计划修正静态显存。平台消费节点，以传输工具计算耗时，通过 h2d/d2h 资源参与 L1 DES；不在平台反推层或改写训练依赖。
- 保留独立 F/B 仿真和 GA 组装。B 内有实际前序计算窗口就预取；首个反向消费者没有窗口时在 B 入口显式加载。接受该阶段屏障下的保守结果，本期不支持 F 中启动传输延续至 B。
- 层内原始前向完成后卸载，在下一窗口结束／缓冲复用边界等待；恢复必须在首次消费（含 recompute）前完成。head 自身不卸载；MTP 按实际依赖和执行实例处理，不依赖层名排序。现有 FSDP wait 不是逐层屏障，复用控制机制时不得扩大原生等待范围。
- 传输作为节点自然参与时间线、算子占比和暴露时间统计；端到端不重复添加后处理拖尾。MBU 分子排除新增激活传输字节，MFU/HFU/MBU 分母使用最终 DES 组装耗时。旧显式窗口补偿与新激活节点同时使用应拒绝。
- 静态内存按 storage 身份去重，覆盖生成、卸载等待、当前消费与预取驻留，并保留仍被其他层使用的共享数据。head 的现存驻留不重复添加；O 阶段不改。本期不是执行时间驱动的动态内存回放。
- 真实 MTP 中存在归属层结束后才产生的 payload。首版显式等待其生产者，对该层采用 F 末排空的保守处理，并在任务日志中告警；这可能减少掩盖机会、使驻留超过相邻两层。后续可按数据就绪边界拆批，当前不伪造提前传输。
- 首期传输使用显式方向带宽／利用率或可注入耗时工具，后续接 topo；不使用 HBM 带宽代替主机链路，不猜测硬件默认带宽。完整 topo、优化器卸载和跨阶段异步执行不在本次范围。

真实 Meta 核对与详细实现依据见[训练仓激活 offload 文档](../torchtitan-npu-simulator/experiments/simulator/docs/activation-offload-design.md)。该确认优先于本文早期后处理及统计段落。

## 2026-11-02 已确认：优化器状态卸载

优化器卸载与激活卸载使用独立开关。训练仓以实际 optimizer-owned storage 得到当前逻辑 rank 的状态总量 S，保留原始状态量用于传输和审计；平台不按世界大小或 GA 放大 S。

- 双向带宽均为单向带宽，链路全双工；以充分逐 tensor 流水的聚合近似，传输时间取 `max(H2D(S), D2H(S))`。例如 S=10 GB，两方向各 50 GB/s，加卸载共同占 0.2 s，不相加成 0.4 s。
- 训练仓对实际优化器更新算子构建共同开始和结束边界，H2D、原有 AdamW 等更新路径、D2H 三路并行，结束等待三路全部完成。保持原更新算子耗时和内部依赖，不将裁剪梯度等整个 O 阶段纳入掩盖窗口。
- 平台通过 h2d/d2h 独立资源和 DES 推演耗时，自然进入时间线、暴露时间及统计；不再追加 `max(0, X-Y)` 补偿，也不把传输时间写入 AdamW 成本。
- 卸载开启时，训练仓交付的 F/B/O 静态峰值均不含优化器状态，忽略逐 tensor 加载缓冲峰值；权重、梯度、激活等其他口径保持。`optimizer_state_bytes` 仍是原始状态总量，不能因设备驻留为零而改为零。关闭时沿用状态在 F/B/O 常驻的稳态口径。平台只读取最终预算，不二次扣减。
- 新增优化器传输不计入 MBU 的 HBM 工作量分子，原有更新算子的工作量保持；指标分母随最终迭代时间变化。O 只执行一次，不乘 GA。
- 该策略是窗口级充分流水近似，忽略启动、排空及搬运缓冲峰值，不代表 CPU 执行 optimizer，也不包含权重/梯度卸载。两个卸载开关的四种组合均须验证原始捕获、节点依赖和静态内存一致性。

### 后续 topo 接入迁移要求

当前 `platform.transfers` 仅为过渡配置。待 topo 完成后，激活和优化器卸载必须共同切换到 topo 配置，通过对应工具 API 获取传输带宽或耗时，不长期保留两套硬件能力来源。迁移需同步 CLI/Python API、配置来源查询、结果中的硬件引用和回归测试，并明确旧配置的兼容／弃用安排；本轮不预定 topo schema 或具体 API 签名。
