Wiki 的安装页集中给出公开镜像引用与 digest，更新页引用安装页。切换推荐版本时，按平台发布记录核对 digest、镜像内技能、示例及产物路径。维护面向无源码用户的步骤时使用 Wiki 链接，并确认匿名读者可以访问。组件已有能力与平台已完成接入分开描述，跨仓摘要以链接为主。

索引按用户任务组织，不要求顺序读完所有文档。普通使用不以开发规范、架构或历史资料为前置；AI 先遵守适用规则，再读取相关专题，遇到依赖问题才扩展阅读范围。

## 更新与历史处理

- 文档优先中文，保留实际代码符号与名称；仓库使用小写连字符，导入包使用下划线。
- 用户新确认覆盖旧建议。改动责任边界时更新当前规范，不在末尾追加一段“替代前文”而留下相互冲突的规则。
- 状态以实现及相应验证为依据；已确认需求、已实现、已验证与待定分开表达。发现业务仓文档漂移时标出真实依据，跨仓任务不擅自替组件制定未定语义。
- 待办写清负责方和待确认点，不把旧仓功能、原型建议或空接口当成已批准范围。完成后移出待办，并链接组件实现/验收。
- 不累加每轮测试数量、临时日志路径和实验数字作为当前状态。运行日志、验收报告和测试产物仅用于当次检查，不入代码仓，也不随发布包或镜像交付。版本追溯仅保留必要的源码提交、基础镜像 digest、依赖及制品哈希、发布镜像 digest 等锁定记录；已有历史材料按需从 Git 追溯，不继续累加。
- 删除历史中间文档前，将仍有效的约束/经验迁入所属主题，更新引用。`docs/bootstrap/` 整体保留为历史启动材料，导航明确非现行规范；原始数据、假设、相对链接不随最新实现改写。
- 跨仓相对链接适用于已克隆的工作区，并提供仓库远端导航；精确验收来源使用固定 revision，日常使用指南可链接当前组件文档。不要把本机绝对路径写成团队前提。

## 跨仓执行与版本

开始前检查各目标仓的分支、HEAD、工作树和适用规则，保留已有改动。确认生产者、消费者及接口迁移影响；实际运行时核对导入路径，不能假定共享目录等于共享环境。

判断当前实现或进行跨仓验收前，先同步远端引用，确认各仓使用的目标集成分支；可快进时快进，再固定精确组合并建立开发 worktree。分支分歧或已有改动不得用 reset 覆盖。无法同步时明确说明使用离线本地基线；本地找不到提交不等于远端不存在，也不能据此判断功能遗漏。修复分支迁移到更新基线后，须重新验证受影响的生产者与消费者组合。

各业务仓独立提交/发布，根仓不纳入业务目录或 gitlink。平台单向验证组合；开发覆盖记录实际路径/SHA/dirty 状态，不能伪装为正式锁定。先验证候选组合，再按组件到平台顺序交付，最终组合需完成相应检查。Portal 消费平台公共入口，只引用平台记录的发布组合与标识，不反向锁定平台。

不提交凭据、个人环境和未说明的运行产物。公共 agent 资料不等于工具会自动加载的技能，按其声明方式使用。分工、单写入者和独立 review 遵循[推荐工作流](../.agents/workflows/multi-agent-development.md)。

## 验证与交付

镜像打包和发布仅在用户明确指令后手动执行，不随代码变更自动触发；暂不建设自动测试流水线或 CI。维护者依据平台仓的 [release-image 技能](https://github.com/ZhanluModelSim/sim-platform/tree/main/.agents/skills/release-image)执行构建和发布。发布记录与 Wiki 同步方式的待决事项见[待办](roadmap.md)。确定性的输入、哈希和依赖检查可保留为小脚本供 SKILL 调用。每次发布保留构建完整性、入口及最小 demo 检查，不默认执行全套仿真或要求结果与旧版数值一致；失败时停止发布。

纯文档修改检查事实、路径、相对链接/锚点、Git 纳入范围及其他仓状态；无需触发训练测试。代码或行为修改按各仓规范验证，区分静态检查、Meta 捕获、synthetic 调度和真实硬件精度。

报告说明修改范围、验证和未完成边界。所有变更遵守[独立分支与 PR 交付规则](../.agents/workflows/pr-only-development.md)，独立任务分支开发并通过 PR 合入，禁止直接推送约定集成分支。提交/推送须符合当次授权，各仓分别操作；管理仓的提交或 bundle 不包含被忽略的业务源码、未提交内容或运行环境。
