# 公共协作与文档规范

本规范适用于工作区管理仓及跨仓工作。业务仓库仍维护自身的工程约定，能够脱离本工作区独立开发。

## 规则归属

- 根 `AGENTS.md` 保存跨仓边界、当前确认和待定问题，是公共规则入口。
- 本文件保存文档及协作流程规范；根 `.agents/` 保存可复用的操作指南、模板和后续技能。
- 业务仓库的 `AGENTS.md` 维护本仓安装、架构、修改与验证规则。修改某目录前读取适用规则，不把根仓历史建议当作业务实现事实。
- 用户新确认覆盖早期建议。涉及边界调整时同时更新当前决策记录；保留历史资料的证据价值，明确哪些部分已经被后续决定替代。

## 文档维护

文档优先使用中文，代码符号保持实际拼写。仓库目录采用小写连字符，Python 导入包使用下划线；产品名与仓库目录名可以不同。

跨仓设计放在本仓 `docs/`，组件内部的设计、使用和测试说明放在对应业务仓库。不要复制一份正文到多个仓库分别维护；用链接和明确版本引用。

`docs/bootstrap/` 是启动评审及实验资料。保存原始数据、假设和证据之间的关联；历史报告中的路径、时间、计数及验证范围不随目录命名调整而改写。导航页应说明当前命名与最新决策入口。

新增设计说明应交代问题、适用范围、已确认内容、建议方案、未决问题和相关源码／证据。没有实现或没有执行的验证，不写成完成或通过。使用相对链接，避免把个人机器的绝对路径写成团队运行前提；已有历史来源路径须注明用途。

## 跨仓工作

开始前检查目标仓库的分支、提交和工作树状态，保留已有改动。记录变更归属及受影响的生产者、消费者。仓库地址只使用已确认来源。

平台集成版本由平台单向管理；根仓只组织开发资料和搭建过程。组件不反向锁定平台版本。业务目录不加入根 Git 索引，不使用 `git add -f` 绕过根仓排除规则。

共享资料不包含凭据、个人缓存、机器专属配置或未说明的运行产物。公共 agent 资料按工具实际发现方式引用或安装，不假定任意 `.agents` 内容都会自动加载。

## 验证与交付

目录及文档修改检查路径、相对链接、Git 纳入范围和业务仓库状态即可，无需触发训练测试。修改行为时按所属组件规则执行相关验证，并区分静态检查、Meta 捕获与真实硬件验证。

报告变更时说明完成内容、验证方式和未完成边界。共享工作区前确认需要交付的文件已经提交；根仓提交不会携带被排除的业务源码，业务代码须通过其独立仓库或独立 bundle 交付。
