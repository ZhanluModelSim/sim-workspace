# 轻量 RSI：有证据的持续改进

本流程用于已明确目标的代码、工具、评估和 Agent 工作方法改进，由主 agent 组织执行。当前不包含自动迭代运行器、定时任务、能力注册中心或新发布系统；本流程不授予额外修改范围、远端操作或长期自主运行权限。

人员分工、单写入者和独立 review 复用[多仓协作流程](multi-agent-development.md)；测试层次复用[Python 开发规范](../standards/python-development.md)，资料归属遵循[文档规范](../../docs/workspace-conventions.md)。用户最新确认优先，参考 demo 的目录和审批政策不自动成为本项目约束。

## 两种改进与职责

- **业务改进**：以可复现案例与行为对比验证捕获、契约、预测、调度或结果的改善。
- **工作方法改进**：调整任务导航、检查工具或接入流程，用后续代表任务检验是否减少遗漏、重复调查和无效返工。写好文档不等于效果已验证。

| 归属 | 承担内容 |
| --- | --- |
| 管理仓 | 公共流程、模板与导航；跨仓职责变化回到现有职责文档，待办回到现有 roadmap |
| 平台仓 | 跨仓集成评估、组件组合及环境证据；正式组合清单、锁定与检查工具由平台建设 |
| 训练仓 | 捕获、模型接入、卸载图与静态内存的案例、验证和经验 |
| 推理仓 | 模型语义、调用计划、状态和捕获的案例、验证和经验；不强套训练 GA |
| 算子仓 | adaptor/模型契约、工作量与公式、覆盖及精度评估 |

这是内容归属，不表示组合锁定工具或自动评估系统已经实现。各仓沿用现有入口、测试和文档，只在有实际消费者时抽取重复验证逻辑；不为形式统一搬动业务包、复制契约或预建空目录。

## ChangeSet：一次改进的关联记录

跨仓改进以一个 ChangeSet 关联目标、相关提交和组合验证；单仓小改动可直接使用任务或 PR 描述，不强制独立文件。它不是任务管理服务，也不意味着多仓能够原子提交或回滚。

使用[轻量模板](../templates/changeset.md)，先填写问题、范围、假设和验收条件，再补实际结果。选择唯一记录位置：已有 issue/PR、任务记录或牵头业务仓的评估记录；其他仓通过同一 ID 和链接引用，不在管理仓复制业务实施档案。记录和证据须可供接手者访问，临时本机路径不能是唯一交接依据。

基线与候选记录所有影响结果的组件精确 commit、dirty 状态及必要补丁/制品引用，附环境与实际导入位置。未执行检查标为未运行，开发证据不自动成为正式集成锁；正式组合按平台既有版本规则处理。

## 评估闭环

1. **发现与定位**：保存失败事实，建立最小复现，区分实现缺陷、组件版本不匹配、环境问题和未定需求；先检查实际组合。
2. **提出假设**：明确预期改善、允许范围、不变量、对照方式和停止条件。多轮试验按任务约定时间/尝试预算，不套用固定仓库数和文件数。
3. **实施候选**：按现有协作流程隔离修改，每次聚焦可解释的假设；超出范围的语义问题交回主 agent 与用户，不自行补定。
4. **同条件比较**：固定负载、硬件、配置、环境与评估方法，只改变声明的因素；记录通过、失败、跳过、未运行及原因。必须改变环境时说明差异，不能声称纯代码收益。
5. **审查与决定**：按风险独立 review，依据原始证据接受、放弃或继续验证。没有改善、出现回归、无法形成有效对照或预算耗尽时停止该轮盲目修补并记录原因；改变范围/预算需说明依据，停止试验不等于目标完成。
6. **交付与沉淀**：按已有授权及依赖顺序交付，核对最终组合；复现提升为回归，有效经验迁入唯一维护位置，放弃候选保留原因。

评估规则应先于候选修改明确。不能通过删除用例、改变预期答案、放宽校验或扩大零成本分类证明成功。业务需求确实改变时，单独说明并审查评估规则变化，不能混同旧口径的改善。

## 评估依据

| 评估类型 | 适用判断 |
| --- | --- |
| 契约与不变量 | 信息透传、依赖保留、重算隔离、耗时修正不改变工作量等；复用已有 tests |
| 代表任务与前后对比 | 固定案例检查全流程和相对变化，不把当前不完整建模的端到端数值锁成永久答案 |
| 设备对照 | 有实际测量来源才判断精度；遵循根 AGENTS 的 DeepSeek-V4 基线与几何、并行、精度、rank 等来源要求 |
| Agent 任务评估 | 观察相关任务的完成、遗漏、人工纠正和返工；记录任务范围/环境差异，不凭一次自述声称普遍提升 |

Meta、synthetic、真实预测与设备测量分别标记，不能互相替代。测试数量不是改善指标；覆盖、性能和耗时变化要说明分母及缺失范围。昂贵实验按风险选择，已通过且未受变更影响的检查不机械重跑。

## 经验沉淀

- 稳定可复现的错误优先变成测试或边界校验；重复诊断优先变成所属仓工具，不只留一句“下次注意”。
- 领域经验更新对应指南/常见问题，保留适用条件、证据和验证方法；跨仓通用步骤才进入 `.agents`。AGENTS 只放必须保持的约束和入口，不积累实验流水账。
- 新任务方法先记为候选经验，经后续代表任务验证再标为有效；新证据推翻时修正或退役旧规则，不并列保留矛盾要求。
- `runs/` 保存临时试验；成为长期验收依据后，将最小配置、断言、复现命令提升到负责仓已有测试/评估入口。大产物保存可访问引用和必要摘要/校验值，不整批纳入 Git。
- 原始证据不随新结论改写；现行指南讲当前机制，历史选择和失败候选通过 ChangeSet、Git 或制品追溯。

## 最小启动方式

选一个已有复现的跨仓兼容问题，记录组件组合，复现失败，提出单一修复假设，执行契约与集成检查，沉淀测试和必要导航。先验证闭环是否有用，不开发自动循环执行器、独立 skills 仓或通用 Capability/MCP Runtime。
