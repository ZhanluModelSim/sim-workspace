# Python 开发与验收规范

适用于工作区内的 Python 开发；新仓以本规范为默认基线，已有仓优先保留自身工具链与上游约束。用户确认的需求优先。各仓通过 AGENTS.md 引用此文，不依赖管理仓才能安装或运行，不复制整套正文。

## 格式与工具

新 Python 包采用 `pyproject.toml`、`src/<package>/`、`tests/` 和明确的 wheel 边界。推荐 pytest、Ruff format/lint 与 mypy strict；使用项目开发依赖中的工具版本，在仓库内执行检查。

当前新仓推荐配置：行宽 100，Ruff 规则 E/F/I/UP/B，mypy 对 src 严格检查。Ruff target-version 与项目最低 Python 版本一致，不能为了统一工具配置擅自提高运行环境要求。各仓最低 Python 版本和依赖以其当前 pyproject.toml 及运行环境为准，不在管理仓重复维护。训练仓沿用现有 120 列及 pre-commit，不全仓重新格式化。

```bash
ruff format --check .
ruff check .
mypy src
python -m pytest
```

上述为新仓基础命令；实际测试目录、系统测试开关及环境要求以各仓文档为准。开发时用 `ruff format` 格式化修改文件；不要通过批量格式变更掩盖行为变更。规则集、Python 版本和必要例外在本仓 pyproject.toml 声明，工具配置不由工作区运行时注入。

## 代码组织与类型

- 模块按职责划分，优先窄接口和组合；出现真实复用需求后再提取抽象，不预建多层基类、注册框架和空包。
- 公共入口及业务函数提供明确的参数、返回类型；用 dataclass、Literal、Protocol 表达数据和扩展边界。协议只包含消费者需要的能力。
- 稳定事实与任务结果优先不可变对象；`frozen=True` 不等于嵌套可变字段不可变，避免共享 list/dict 泄漏。运行状态、缓存与事实分别保存。
- 边界上的动态数据先校验再转为内部类型。`Any`、`cast`、`type: ignore` 仅用于有依据的第三方边界，保持局部并说明原因，不用它们掩盖不清晰接口。
- 名称反映语义和作用域，单位在字段名或契约中明确；缺失、未知、零值是不同状态，不能用真假判断混为一谈。
- 注释和 docstring 用英文解释不明显的语义、约束及取舍；项目文档优先中文。避免逐句翻译代码式注释。

## 错误、配置与副作用

- 输入错误显式抛异常；assert 只用于内部不变量和测试，不承担可被优化关闭的输入校验。
- 不吞掉宽泛异常，不将未知预测、缺失依赖或非法数据伪装为成功；fallback 只处理协议允许的明确失败类型。
- 数值入口按语义校验范围、有限性和整数性，注意 bool 是 int 的子类；缓存键显式区分会影响计算的类型与配置。
- 共享默认配置集中管理、可查询来源；单任务冻结快照，任务参数和运行状态独立。组件不能反向依赖平台全局对象。
- 可选训练／设备依赖在需要时加载；避免纯图或预测接口导入时启动设备环境、修改进程配置。已有插件导入副作用遵循其本仓规则。
- 数据事实、预测、修正结果和执行时间线分离；分类、耗时和资源需求独立表达，纯元数据节点也保留依赖。

## 测试与审查

按变更风险选择测试，避免只镜像实现或断言源码文本：

1. 单元测试：语义边界、非法输入、错误路径、确定性以及本次修复的回归。
2. 模块测试：生产者与消费者衔接、配置隔离、缓存失效、资源竞争和跨阶段依赖等真实交互。
3. 系统测试：代表性真实负载贯通入口和输出；昂贵或设备相关测试显式启用。记录环境、实际导入路径和覆盖范围。
4. 交付测试：构建 wheel，在源码目录外普通安装并运行有意义的冒烟；不使用 PYTHONPATH 或 sys.path 修改替代安装。

Synthetic 成本只验证调度和流程；Meta 捕获不证明数值正确或硬件性能精度。记录 passed/failed/skipped/not-run 及原因；不把旧结果当作改动后的验证。文档修改仅做链接、事实与 diff 检查，不因此重复昂贵系统测试。

架构、公共契约、调度、缓存等重要实现交由未参与实现的 reviewer 审查；主 agent 核实问题、补回归、修复后复核。审查关注行为与设计复杂度，不只检查格式。明确说明无遗留阻塞项和仍未实现的范围，不能把“未发现问题”写成绝对正确。

## 提交与交付

提交前核对分支、远端、文件范围与 diff，排除缓存、环境、产物和凭据；保留已有用户改动。多仓变更先组件、后平台集成，各仓独立提交，根仓不纳入业务仓源码。

遵守[独立分支与 PR 交付规则](../workflows/pr-only-development.md)，只推送独立任务分支并通过 PR 合入；禁止直接推送约定集成分支。发生分歧先分析和整合，不强推覆盖。提交信息描述具体行为或文档变化。平台记录已验证组件的精确提交及环境；尚未提交的开发组合不能伪装成发布清单。推送完成后核对远端提交和工作树状态。
